In his talk *"Anthropic's CCA Exam as a Field-Guide for Agentic Engineering,"*  Frank Coyle breaks down key agentic engineering design scenarios, contrasting the recommended **Patterns** against the risky **Anti-patterns** .

Here is the summarized breakdown in Markdown format:

| Scenario | Pattern (Sound Architecture) | Anti-pattern (To Avoid) |
| --- | --- | --- |
| **1. Customer Support Resolution Agent** | **Explicit Stop Reason Control & Human-in-the-Loop:** Loop through responses using `stop_reason` checks (e.g., `tool_use`, token exhaustion) . Intercept tool calls, execute them in code, evaluate confidence scores, and escalate to a human if necessary . the agent knows what is not allowed to resolve on its own. | **Unchecked Execution / Blind Assumed Output:** Letting the agent loop continuously without inspecting `stop_reason` , or relying on partial responses generated after running out of tokens. No huamn-in-the-loop.|
| **2. Code Generation with Claude**  | **Hierarchical Configuration Rules:** Utilize nested rules files (`CLAUDE.md`) . Layer instructions by scope: user, project, dicrectory. Claude loads all threee and merges them. The most specific file wins on any conflict.  plan before you execute. | **Monolithic / Unstructured Project Instructions:** Dumping all system rules, project guidelines, and sub-directory instructions into a single un-scoped instruction file.  No plan mode on changes, direct-execute everything. |
| **3. Multi-Agent Research System**  | **Specialized Single-Purpose Sub-Agents:** Create specialized agents with minimal, targeted tools . Pass only necessary input slices (e.g., claim and evidence) without passing whole thought traces to prevent agent groupthink .  Give each agent a role and a small toolset.   Isolate subagent context, Hub-and-spoke: subagents receive only the slice they need, never the coordinator's full deliberation, so they don't inherit anchoing bias| **Overloaded Swiss-Army-Knife Agents:** Creating a single agent overloaded with many general-purpose tools , or allowing sub-agent context and internal thought reasoning to spill into the primary orchestrator context . |
| **4. Developer Productivity (Code & Logs)**  | **Subtask Isolation & Context Compaction:** Fork heavy tasks (like scanning error logs) into isolated subprocesses . Return only summarized outputs to the primary thread, and invoke compaction/compression routines when token counts exceed thresholds . | **Unbounded Context Pollution:** Allowing every subtask thread to dump its full stdout/raw log traces into the primary conversation window, flooding the context limit . Pollute the main session & Let context grow unbounded |
| **5. Continuous Integration / Pipelines (Claude Code)**  | **Non-Interactive Execution & Batch API:** Configure CLI agent pipelines to run in non-interactive headless mode . Offload non-urgent, heavy workloads to Batch processing for 50% lower token costs . | **Interactive Prompts in Automated CI/CD:** Running agent tools in interactive modes that pause and require human prompts/permission prompts inside headless CI pipelines .  Block on work that can wait. Forcing a synchronous, latency-sensitive call for batch-friendly work. paying full prie and stalling the pipeline.|
